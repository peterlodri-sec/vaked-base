# Plan: `vaked fmt` — AST-based formatter for Vaked source files

## Context

The Vaked language needs a canonical formatter (`vaked fmt`) to enforce consistent style across all `.vaked` files. This eliminates style debates, makes diffs clean, and enables CI formatting gates. The formatter is AST-based: parse → AST → emit, ensuring round-trip safety and idempotency.

## Current state

The `vakedz` compiler has a working lexer (358 lines) and parser (712 lines) with full AST types, but **no CLI infrastructure**: `main.zig` is a 12-line hello world, and there is no `build.zig` (only `build.zig.zon`). The `crossverify.sh` script expects subcommands (`parse`, `check`) that don't exist yet. This plan includes the minimal scaffolding needed to wire `fmt` into a working binary.

## Formatting rules (derived from examples)

| Construct | Format |
|-----------|--------|
| Declaration | `kind name {` / `}` — 2-space indent body |
| Annotation | `@name` or `@name(args)` on its own line before the decl |
| Signature | `(param: Type, ...)` inline with the name |
| Assignment | `target = value` (or `target ?= value`) |
| Field decl | `field name : Type` or `field name : Type { refinements }` |
| Refinement block | one per line, 4-space indent from decl start |
| Grant decl | `grant name1 name2 ...` |
| Order decl | `order chain1 ; chain2` with chain continuation on next line indented |
| Member decl | `member name` |
| Node decl | `node name { body }` |
| Edge | `ref -> ref : "label"` (label optional) |
| App/expr | compact, no unnecessary spaces |
| List literal | `[a, b, c]` inline if short; multiline if >80 chars |
| Record literal | `{ key = val }` inline if short; multiline with 2-space indent otherwise |
| Import | `use "path"` |
| Blank lines | one between top-level decls; none within a block unless separating logical groups |
| Trailing newline | exactly one trailing newline at end of file |
| Indent | 2 spaces per level |

## Files to create/modify

### 1. `vakedz/build.zig` (new — prerequisite for everything)

Minimal build script that builds the `vakedz` binary from `src/main.zig` and registers a `run` step.

```zig
const std = @import("std");

pub fn build(b: *std.Build) void {
    const target = b.standardTargetOptions(.{});
    const optimize = b.standardOptimizeOption(.{});

    const exe = b.addExecutable(.{
        .name = "vakedz",
        .root_source_file = b.path("src/main.zig"),
        .target = target,
        .optimize = optimize,
    });
    b.installArtifact(exe);

    const run_cmd = b.addRunArtifact(exe);
    run_cmd.step.dependOn(b.getInstallStep());
    if (b.args) |args| run_cmd.addArgs(args);
    const run_step = b.step("run", "Run vakedz");
    run_step.dependOn(&run_cmd.step);

    const unit_tests = b.addTest(.{
        .root_source_file = b.path("src/main.zig"),
        .target = target,
        .optimize = optimize,
    });
    const run_unit_tests = b.addRunArtifact(unit_tests);
    const test_step = b.step("test", "Run unit tests");
    test_step.dependOn(&run_unit_tests.step);
}
```

### 2. `vakedz/src/Args.zig` (new — minimal CLI dispatch)

Parses argv into a tagged union. Only `fmt` is implemented initially; others stub with an error message.

```zig
pub const Command = union(enum) {
    fmt: struct { paths: []const []const u8, check: bool, stdout: bool },
    parse,
    check,
    lower,
    cache,
    help,
    version,
};

pub fn parse(allocator: Allocator, args: []const []const u8) Command { ... }
```

Flags:
- `vaked fmt <paths...>` — format in-place (default)
- `vaked fmt --check <paths...>` — exit 1 if any file would change (CI gate)
- `vaked fmt --stdout <path>` — print formatted result to stdout

### 3. `vakedz/src/Fmt.zig` (new — the formatter core)

**Architecture:** `Fmt` takes a `[]const parser.Item` (the AST) and writes formatted source to a `std.ArrayList(u8)`.

**Key functions:**
- `pub fn formatFile(arena, items, out) !void` — entry point
- `fn formatDecl(arena, decl, indent, out) !void`
- `fn formatStmt(arena, stmt, indent, out) !void`
- `fn formatExpr(arena, expr, indent, out) !void`
- `fn formatRef(ref, out) !void`
- `fn formatAnnotation(ann, out) !void`
- `fn writeIndent(indent, out) !void`

**Design decisions:**
1. **Idempotent:** `fmt(fmt(src)) == fmt(src)` — guaranteed by AST round-trip
2. **Comments are lost:** The current lexer discards comments. The formatter cannot preserve them. This is a known limitation documented in the GitHub issue. A future `lexWithComments` pass can fix this.
3. **Whitespace normalization:** All significant whitespace is normalized; insignificant whitespace (spaces within expressions, trailing spaces) is removed.
4. **Line length:** No hard wrap at 100 chars — Vaked's block structure makes wrapping rare. Lists/records that exceed terminal width stay on one line (users can manually break with newlines inside `()`/`[]`).

### 4. `vakedz/src/main.zig` (modify — wire CLI)

Replace the hello-world with:

```zig
pub fn main() !void {
    var gpa = std.heap.GeneralPurposeAllocator(.{}){};
    defer _ = gpa.deinit();
    const allocator = gpa.allocator();

    const args = try std.process.argsAlloc(allocator);
    defer std.process.argsFree(allocator, args);

    const cmd = Args.parse(allocator, args[1..]);
    switch (cmd) {
        .fmt => |f| try fmtCmd.run(allocator, f),
        .parse, .check, .lower, .cache => {
            std.debug.print("vakedz: {s} not yet implemented\n", .{@tagName(cmd)});
            std.process.exit(1);
        },
        .help => std.debug.print("usage: vakedz <fmt|parse|check|lower|cache> [args]\n", .{}),
        .version => std.debug.print("vakedz 0.1.0\n", .{}),
    }
}
```

## Limitations / future work

- **Comments lost:** Lexer discards comments; formatter cannot preserve them. Fix: add a `lexWithComments` mode or a trivia-preserving token type.
- **Only `fmt` subcommand:** `parse`, `check`, `lower`, `cache` are stubbed. The issue scope is fmt-only.
- **No `--diff` mode:** Could be added later (show unified diff of changes).

## Deviations (as implemented)

- **Multi-entry records emit multiline, not inline.** The grammar separates record
  entries by newlines only — the parser rejects commas inside `{ … }` — so the
  "inline if short" rule above is unimplementable for more than one entry (the
  output would not re-parse). Rule as built: a single short entry stays inline
  (`{ key = val }`); anything else emits as a multiline block at +2 indent.
- **Comments ARE preserved.** The lexer carries comment tokens (commit 88d4f62) and
  the parser/formatter attach them as items/statements; design decision 2 above
  ("Comments are lost") and the matching "Limitations" bullet are obsolete.
- **Refinements format inline space-separated** (`field x : T { required >= 0 }`),
  matching every file in `vaked/examples/`, not the rules table's "one per line,
  4-space indent from decl start".
